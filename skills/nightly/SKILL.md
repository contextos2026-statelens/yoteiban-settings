予定ばんの毎晩の見直し

まず「予定ばんの運用ルール」を読み、正本の章を切り出して読む：`cd "$YOTEIBAN_REDESIGN_LIB" && python3 -m yoteiban_rd.rules_slice --task nightly`（第2・10・14・18・19・20.1・20.3・20.4・20.6・20.8・22・23・25章）。終了コード3なら全文を読んで続ける。版はGitの `VERSION` に従い、本文に版番号は直書きしない。個人の値（名前、カレンダーID、入口の住所、鍵、URL、控えの置き場の名前）は、このスキルに書かない。記憶と箱の設定から読む。
場面で足す章：予定調整の案（枠・移動の余裕・先読みの見る範囲・合わないときの直し方）を作る → --add 21.1,21.4,21.7,21.8,21.9／他の人の返事待ち → --add 24:使わない設定,24:返事を追う,24:返事の読み方。

このスキルは予定ばんのスキル群の1つです。毎晩の台帳（決まった仕事。いまは毎日21:45ごろ）と、先回りの案を作るときに読みます。動く前に必ず「予定ばんの運用ルール」も読みます。大原則と安全の線は「予定ばんの運用ルール」が最優先で、他のスキルの文と食い違う時は安全な方（書かない・送らない・消さない・聞く）を選びます。ほかのスキルの【】の項目名が出てきたら、そのスキルも読みます。重なりの選択肢の出し方は「予定ばんの予定調整」、朝のまとめの書き方は「予定ばんの重要度と通知」に従います。
現行の「毎晩の見直し」の決まった仕事は停止中で、毎晩の台帳に置き換わっています。停止中の仕事を、本人の「はい」なしに動かし直さない。

【台帳への記録（v2.3。運用の正は台帳）】
先読み・監査・控えの結果の、運用上の正は台帳です。置き場の正は箱の設定。読めないときは「新しい台帳は未確認」と書き、無いものとして扱わない。この仕事で使う表は次のとおりです（個人の値は書かない。列がまだ無いものを使うときは「未確認」とし、勝手に列を足さない）。
- 先読み `outlook_findings`（key・type・date・refs・urgency・text・status・first_seen・last_seen）と、日ごとの作り直しの印 `outlook_days`（date・built_at・digest）。同じ key は二重に作らず、last_seen を新しくする。
- 写しの照らし合わせ `mirror_checks`（at・target・diff）。夜間監査は target を「nightly」で残す。照合の見回りは「interval」。
- 控え `backups`（at・path_ref・bytes）。
- 案件 `cases`・質問 `questions`・提案の案 `plans`・つながり `case_links`：読むだけ（直すのは本人の言葉と「はい」の後、または各スキルの手順の中だけ）。
読み書きは、運用ルールの【道具】と同じ核（設定の `tools.repo` または環境変数 `$YOTEIBAN_REPO`。読み込み先 `PYTHONPATH="$YOTEIBAN_REPO/core:$YOTEIBAN_REPO/redesign/lib"`）。
- 先読み：`yoteiban_core.lookahead` の run（events・cases・today・settings・weather・travel_min・days。既定7日。重なりと移動の無理を見る範囲）。コマンドは無く、Python から呼ぶ。ずらし先探し（1週間→2週間→3週間）は下の計算係 nightly。
- 夜間監査：`python3 -m yoteiban_core.audit --config <設定>`（標準入力に、読んだカレンダー・リマインダー・Notion の写しを JSON で渡す）。
- 保持期限：`yoteiban_core.retention` の purge（Python から呼ぶ）。
- 控え：`…/repo/ops/backup/box_snapshot.sh <台帳> <公開鍵> <送り出し用フォルダ> <core>`（核の `python3 -m yoteiban_core.backup snapshot` を使う。公開鍵で暗号化し、平文の台帳は箱の外に出さない）。
- 先回りの案：計算係 `python3 -m yoteiban_rd.cli nightly`（下の手順3）。
鍵・設定の中身・控えの置き場の値は、このスキルにもチャットにも書かない。
Notion の8つの表は、本人が見る表として残す。移し替えは 2026-11-19 に済み。台帳だけを正として読み書きし、Notion は昔の記録を確かめるときだけ読む。新しい表は作らない。

【手順（毎晩の台帳）】
1. 集める（何も書かない）：台帳の開いている案件と、記憶の『読む先の一覧』のカレンダー全部（個人用・家用の primary・ファミリー。読むだけ）。先読みも先回りの案の重なり・移動も、今日から1週間（7日。2026-11-19 本人決定）。その日でなくてよい予定のずらし先は、1週間、無ければ2週間、3週間と広げる（3週間までなら、見る範囲の外も、ずらし先探しのためだけに読む。計算係 nightly が行う）。重い締切の手順分けとお祝いだけは、計算係が少し先まで見る。下書きカレンダーは作らない（2026-11-19 本人決定）ので読まない。家用・ファミリーの予定は第22章で本人・全員・本人以外・わからないに分ける（見分けの表を先に読む）。1つでも読めなければ、その入口を「未確認」として残し、「予定なし」とは扱わない。
2. 先読み：上の先読みにかけ、見つかった重なり・移動・準備不足などを台帳の `outlook_findings` に入れる（列の決まりは上のとおり。専用の書き込み関数は核にまだ無いので、列と同じ key の決まりを守る。入れられなかったら記録だけ残し、本人に知らせるのは朝のまとめの「確認してね」に1行）。前の晩から変わった日だけ作り直してよい（同じ場所の rerun）。
3. 先回りの案：計算係の nightly に渡す：
   `cd "$YOTEIBAN_REDESIGN_LIB" && echo '<JSON>' | python3 -m yoteiban_rd.cli nightly`
   入力：{"now", "cases": [...], "events": [{"id","title","start","end","calendar"（personal／household／family）,"owner"（self／all／other／unknown）,"kind"（move／prep／meal など）,"location","all_day","meta"}], "goals": [記憶の目的の一覧], "previous": <昨日の結果そのまま>, "feedback": "$YOTEIBAN_STATE/nightly/feedback.jsonl", "coverage": <coverage の結果>, "horizon_days": 7}。計算係の範囲の既定は7日。ずらし先探しは 7→14→21 日（重い締切の手順分けとお祝いだけは、少し先まで見る）。
   返り値：morning（急ぐ順の3件。朝のまとめに載せる）・record_only（score が1以上はあふれた案で2通目に全部出す。0は記録だけ）・weekly（2回出して返事が無いので週次へ）・suppressed（「外れ」と言われたその1件だけ、30日出さない）・diff（新しい・続き・片付いた）・feedback_card（当たり外れを聞くカード、1日1枚）。
4. 読み直して、計算係にできないことを足す（ここが考える仕事）：
   - 別々の案件どうしのつながり（同じ土地・同じ家族・同じ行事）。計算係が「つながり」「まとめ」にしたものは、本当に同じ原因かを確かめ、違えば分ける。
   - 目的の一覧（記憶と台帳の目的）と照らした優先の順。目的に近いものを上にする。
   - 空振り（本人がもう済ませた・関係ない・まだ先で今は動けない）を外す。
   - 昨日の案との違い（diff）を見て、続きのものは「昨日から」と分かる言い方にし、片付いたものは記録だけにする。
   - 先読みの結果と先回りの案が同じ件なら1つにまとめる。
   - 手順分けは、計算係が出した空き枠（本人の予定と重ならない）を使う。本人の進み具合が分からないときは、最初の1手だけを出す。
   - 計算係が出したずらし先を検算する。相手のいる予定・動かせない時刻・家用の予定のずらし案は外す。
   - 目的（何のため）と方法（どこで・どうやって）を分け、方法を変えても目的が果たせる別案を足す（近い店で買う、オンラインで出る、など。買う・予約・支払いはしない。調べた店・経路は「未確認」と出どころ）。有力な案が無ければ、その旨を朝のまとめで報告する一行を残す。
5. 夜間監査：写し（カレンダー・リマインダー・Notion）と台帳を照らし、手続きの印の無い書き込み・「実行結果不明（要照合）」の残り・承認の期限切れ・止まった仕事を `mirror_checks` に残す。見つけたものは朝のまとめの「確認してね」に1行ずつ（直すのは本人の「はい」の後）。
6. 保持：保持期限の処理を流す（保持期限 retention_until を過ぎた入力は、伏せ字の要約があるものだけ本文を消す。要約が無いもの needs_summary は消さずに残し、記録する）。
7. 控え：暗号化した控えを作り、決まった置き場へ送る。家の機械側で許可の確認が出たら、そこで止めて朝のまとめの材料に「控えの送り出し待ち」と残す。控えが2晩続けて失敗したときだけ、本人に1行で知らせる。
8. 失敗したことは、箱の記録（`$YOTEIBAN_STATE/v23/logs/` の夜の記録）に段階・時刻・理由だけを残す（本文や個人の値は書かない）。
9. 朝の案：先回りの案は件数の上限なしで、全部出す（2026-11-19 本人決定）。計算係 nightly は morning を急ぐ順の3件に絞り、あふれた案を record_only に入れる（コードは今のまま）。そこで、朝のまとめには morning（急ぐ順に3件まで）を載せ、record_only のうち score が1以上のもの（上限であふれた案）は、朝のまとめ直後の2通目の表に全部入れる。score が0のもの（まだ先で今は動けない・記録だけと決めたもの）は今までどおり記録だけ。weekly（2回出して返事が無いもの）は週の見直しの一覧。 朝のまとめ本文に載せるのは急ぐ順の3件まで。1件は「何に気づいたか／案（2つまで。記憶の好みに案の数があればそれに合わせる）／やること1つ」。問いは本文に書かず、質問カードで1つずつ（朝のまとめの書き方は「予定ばんの重要度と通知」）。家用だけにある本人の予定（kind が「家用だけ」）は、その日の朝のまとめの📅予定に載ることを確かめる（載せるのは朝のまとめの道具 morning）。朝の案は 2026-11-20 の朝から出す（並走は取りやめ。2026-11-19 本人決定）。
10. 何も変えない。カレンダー・リマインダーに書くのは、朝に本人が承認した後だけ（手順分けの枠も同じ。強制追加と［仮］の例外は、この夜の仕事では使わない）。勝手に候補を増やさない。送らない。夜に本人へ知らせない（例外は2つだけ：控えの2晩続けての失敗の1行と、下の夜の質問カード）。
   夜の質問カード（2026-11-19 本人決定。夜は黙る決まりの、ただ1つの例外）：朝に聞くことが多すぎる（質問カードが5枚を超える。私の目安）とき、その残りのうち今日（翌日の朝から見た当日）の予定に関わらないものだけは、毎晩の台帳の後に、質問カードで1枚ずつ聞いてよい。知らせ（通知の文）は出さない。今日の予定に関わるものと急ぎのものは、夜に回さず、朝と【夜】の表のとおり。 夜に聞くときは、本文ではなく「カードで聞くこと」の一覧を親に渡し、親が本人とのチャットで1枚ずつ聞く。答えは台帳に残す（当たり外れのカードは今までどおり朝に1日1枚）。
11. 結果を全部残す：今夜の nightly の返り値をそのまま `$YOTEIBAN_STATE/nightly/<日付>.json` に置く（明日の previous になる）。載せなかったものも残す。何も無い夜は朝に何も出さない。
12. 週次レビューでは、台帳の完了確認から「できた／一部できた／できなかった」の件数を1行で加える。合計0件なら行を出さない。予定の内容・場所・他の人の名前は一覧へ複写しない。

【当たり外れ（毎日）】
- 朝のまとめのあと、feedback_card があれば質問カードで1枚だけ聞く（当たり／外れ／まだ分からない）。1日1枚のまま（2026-11-19 本人決定）。
- 「外れ」で止めるのは、その1件だけ（同じ種類・同じ予定や案件・同じ日付）。同じ件名でも、別の日・別の回の案は止めない（例：同じ名前の通院でも、回によって中身が違う用事は、回ごとに別の件として出す）。30日たてば、その1件も出せるようになる。
  照合の鍵：予定や案件の参照がある案は、その参照（回ごとに違う）。参照の無い案は、種類・日付・件名。どちらも計算係が決めるので、頭の中で鍵を作り直さない。
- 種類ごと止める・出し方を変えるのは、週の見直しで本人に1回聞き、「はい」の後だけ。「外れ」1つで種類を止めない。
- 答えを記録する：`echo '{"path": "$YOTEIBAN_STATE/nightly/feedback.jsonl", "key": "<カードの key>", "verdict": "<答え>", "at": "<今>", "title": "<1行>"}' | python3 -m yoteiban_rd.cli feedback`
- 週の見直し（記憶の曜日と時刻）で、`python3 -m yoteiban_rd.cli hit-rate`（{"path", "now", "days": 7}）で当たり率を出し、補足に1文で書く。「外れ」が続く種類は、出し方を変える案を本人に1回だけ聞く（決まりを変えるのは本人の「はい」の後だけ）。

変更の記録は Git の CHANGELOG.md に従う。

【カード回答と再掲】
台帳の `card_answers` をnightlyの入力に渡す（または `ledger_path` を指定して読む）。答えのあるカード鍵は morning と record_only の両方から外す。「出して」は案づくりへ回す印として保持する。record_only も `shown` を引き継ぎ、2回表示したら weekly に回す。「まだ」で記録された `next_review_at` が未来の案件は「過ぎた」に出さず、次回確認日を過ぎたら再評価する。機会は期日の7日前（仮）に1回だけ再掲できる。カードを出したのに答えの記録が3日続けて0件（仮）なら補足に1行出す。
