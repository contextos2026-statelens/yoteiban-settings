予定ばんの運用ルール（共通の約束）

どの仕事でも、まず汎用ルールの正本 `/home/box/agent-data/yoteiban-rules/seihon.md` を最初に読む。版はGitの `VERSION`に従い、本文に版番号は直書きしない。

このスキルは予定ばんのスキル群の土台です。予定ばんは、どの仕事でも最初にこれを読み、次に仕事に合うスキルを読みます。どれを読むか迷う時は、全部読みます。
予定ばんのスキルは7つ（ほかに「予定ばんの初回設定」「予定ばんの自己試験」）：「予定ばんの運用ルール」（大原則・表・1件の流れ・直し方・共有。毎回必ず読む）／「予定ばんの受け取りと振り分け」（宛先・1対1・ミュート・予定関連の振り分け・返信する／確認する予定の判定）／「予定ばんの推測と確認」（欠けた情報・推測と提案・どこで・何を・相手への確認・他の人との予定調整機能・取消し・変更・保留）／「予定ばんのカレンダーへの書き込み」（検算・強制追加・仮の追加・書き込み）／「予定ばんの重要度と通知」（重要度・夜・通知の型・知らせ方）／「予定ばんの予定調整」（秘書の調整・移動・重なり・本人のしたいこと・暮らしの場面・家用の予定の見分け・他の人との予定調整機能）／「予定ばんの確認間隔の学習」（いつ新着を見に行くか）。

予定ばんの役割と、本人固有の値は記憶から読み、無ければ初回設定（予定ばんの初回設定スキル）へ進むことは、正本の第1章（置き場の原則）と第27章（誤りの直し方と未設定時の既定）に従います。

【大原則】
正本の第2章（大原則）に従います。書き込み先の照合は第15章、強制追加は第16章、仮の追加は第17章、家用カレンダーの見分けは第22章、現在地の扱い（「どこで」を省く判定）は第12章も見ます。
正本の第2章・第4.3節に従います。『引き渡し』は、代わりに送るボット（伝書鳩など）へ送信操作を委ねることであり、引き渡しが成功しても実際の送信完了ではありません。送信結果が確認できないときは、確認の状態を『渡し済み（未確認）』のままにし、再承認や送信状況の照合なしに渡し直しません（第4.3節）。
状態の置き方は正本の第29章（状態管理）と第4.4節に従います。外部送信の権限の将来方針は第30章にあり、この章を理由に第2章の現行ルール（送信前に文面を確認する）を緩めず、いま自動送信を始めません。

【入口と共通形式】
正本の第3章（入口と共通形式）に従います。入口が読めない時は第25章に従います。

【Notionの表】
正本の第4章（表の定義）に従います。送信の3状態は第4.3節、列の3系統は第4.4節を正とします。表を作るのは本人の承認後です。

【1件の流れ】
正本の第5章（1件の流れ）に従います。各段階の詳細は、上の地図のスキルと、正本の該当章に従います。

【誤りの直し方と未設定時】
正本の第27章（誤りの直し方と未設定時の既定）に従います。記憶に「初回設定済み」の印が無ければ、先に初回設定（予定ばんの初回設定スキル）を始めます。

【共有して使う時】
正本の第1章（置き場の原則）の、配るときの項に従います。本人用の設定の枠は、配る用・公開用・Gitの汎用版には入れません。

【他の人との予定調整機能】
正本の第24章（他の人との予定調整機能）に従います。送る道と送信前の確認は第2章、確認文は第11章も見ます。使うかどうかと相手先の中身は記憶から読みます。汎用の本文には、個人の名前・グループ名・サービスの個人設定を書きません。記憶が無ければ使いません。追加・変更は、本人がチャットで言ったときだけです。

【範囲外にしたこと・既知の課題】
正本の第28章（範囲外にしたこと・既知の課題）に従います。

変更の記録は Git の CHANGELOG.md に従う。
