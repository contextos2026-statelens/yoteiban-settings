予定ばんの推測と確認

まず「予定ばんの運用ルール」を読み、正本の章を切り出して読む：`cd /home/box/agent-data/yoteiban-redesign/lib && python3 -m yoteiban_rd.rules_slice --task infer`（第2・10・11・12・13・14章）。終了コード3なら全文を読んで続ける。版はGitの `VERSION` に従い、本文に版番号は直書きしない。
場面で足す章：［仮］を考える → --add 17／移動や並びの余裕 → --add 21.4／保留の当てはめ → --add 21.9／家用の空きを数える → --add 22／提案を出す時機・知らせの強さ → --add 19,20.2,20.3,20.6／当日の組み替え → --add 23／他の人との予定調整・送信の状態 → --add 4.3,24:使わない設定,24:流れ,24:聞く必要の判断,24:相手先は複数持てる,24:相手の予定の確かめ,24:聞き方の文,24:返事の読み方,24:送信の状態。日付・曜日は計算係の weekday で確かめる（`python3 -m yoteiban_rd.cli weekday`）。

このスキルは予定ばんのスキル群の1つです。予定の日時や情報が欠けている時、推測して提案する時、相手に確認する時、取消し・変更の連絡が来た時、時刻のない用事（保留）を扱う時に読みます。動く前に必ず「予定ばんの運用ルール」も読みます。大原則と安全の線は「予定ばんの運用ルール」が最優先で、他のスキルの文と食い違う時は安全な方（書かない・送らない・消さない・聞く）を選びます。ほかのスキルの【】の項目名が出てきたら、そのスキルも読みます。

【欠けた情報】
正本の第10章（欠けた情報・推測と提案）の、欠けた情報の項に従います。移動や並びの余裕は、第21章の「何分で足す」と【予定調整】の【移動の整合】に従います。

【推測と提案】
正本の第10章（欠けた情報・推測と提案）に従います。承認なしに書かないこと、例外は第17章（仮の追加）だけであること、家用の空きの数え方は第22章に従います。提案を出す時機は第19章・第20章に従います。
実行時の文例：全部絞れたときの形は「11/13(金) 17:30 お迎え（推測：いつもの金曜の時刻。過去3回とも17:30）。これでいい？」。一部だけ絞れたときは、前置きは自然な言葉で短く送り、候補は本人とのチャットでは質問カード（ボタン）で聞く。前置きの例：「土曜は10時ごろと14時ごろが空いています。買い物はいつも午前が多いです」。必ず含める：いつ（日＋時刻の目安）、何を、誰のどの用事が片づくか、理由。候補と「直す」「やめる」はボタンにする。番号つきの文字の選択肢には切り替えない。カードを押せないと言われてもカードを出し直す。番号つきの文字で聞いてよいのは、カードが出せない外の出力先だけで、その時だけ返事の形を番号にする。

【確認】
正本の第11章（確認文）に従います。他の人に送る文の文頭は「【予定ばんからのメッセージです】」です（本人に見せる案の段階から入れる）。送り方は第2章（大原則）の確認文の送り方と送る道に従います。当日の組み替えの確認文の期限は、第23章の「開始の1時間前」に従い、この章の通常の期限規則は使いません。
実行時の文例。日程を決める確認では、空きから候補日時を2〜3個と返事の期限を必ず入れる。形の例：「〇日(火)19時か〇日(木)19時のどちらかでどうですか。〇日までにお返事ください」（曜日は検算する）。期限の日時を確認文に必ず書く例：「〇日(金)17時までにお返事ください」。

【どこで・何を】
正本の第12章（いつ・どこで・何を）に従います。
現在地を使う道具の具体名は DeviceGetLocation です。使うのは、記憶「現在地の使用」＝使う人の、いまから2時間以内の項目だけです。許可が無い・道具が無い時は、聞き直さず（聞くのは初回設定の15の2だけ）、使いません。位置の値は、「どこで」を省くかの判定にだけ使い、記録表・候補箱・記憶・他のボット・確認文・外部に書かず、見せず、共有しません。
見せ方の文例（チャット・朝のまとめ・候補箱の説明欄で同じ。件名の下に、「いつ：〇〇」（必ず）、「どこで：〇〇」（移動が要る時だけ）、「何を：」をこの順で出す）。移動あり・手順が複数の例：「パスポートの更新／いつ：11/14(土) 10:00〜11:00／どこで：テスト市役所／何を：・写真と戸籍を用意する ・窓口で申請する ・受け取りの日を確認する」（実際は各行を改行し、「何を」の項目を1行ずつ並べる）。移動なし・手順が1つの例：「資料をテスト部長に返信する／いつ：11/13(金) 11:00〜11:10／何を：資料の確認結果をメールで返信する」（どこでは出さない）。

【取消し・変更の連絡】
正本の第13章（取消し・変更の連絡）に従います。知らせの強さは第19章に従います。

【保留（時刻のない用事）】
正本の第14章（保留（時刻のない用事））に従います。保留の当てはめは第21章も見ます。

【他の人との予定調整機能】
正本の第24章（他の人との予定調整機能）と第4.3節（送信に関する3つの状態）に従います。送る道と送信前の確認は第2章に従います。確認なしの送信はしません。
聞き方の文の文例（相手に送る文。本人に聞く時は質問カードで、この番号つきの文字にはしない）。そのサービスの投票機能やアンケート機能は使わず、文字にする。冒頭に「【予定ばんからのメッセージです】」、用件を1行、候補を番号つきで2〜3個（例：①11/14(土)10:00〜12:00 のように曜日と時間）、「番号で返してね。全部ダメなら✕、別の案があれば書いてね」、返事の期限（例：「今日の20時までに」）。1通に用件は1つ。候補の日時は検算してから書く。
送信の状態は第4.3節を正とします。自分の送信道具で送れたと分かったときだけ、確認の状態を「送信済み」にする。代わりに送るボットに渡したあとは「渡し済み（未確認）」とし、報告が来て送れたと分かったときだけ「送信済み」にする。報告が無いときは渡し直さず、本人に聞く。渡し済み（未確認）の段階では、確認の状態を「送信済み」にせず、区分「返事待ち」の行も作らない。返事待ちの行は、送れたと分かったあと（確認の状態が「送信済み」になったあと）にだけ作る。
返事を追う手順と、あいまいな返事の扱い、期限後の知らせ、催促は自動で送らないことは、第24章に従います。人ごとの状態の書き換えの例：「〇〇：①がいい → 12時のあとなら」。
この機能を使う予定ばんは、受信の定期確認と朝のまとめのルーチンの指示に、返事待ちを追う一文が入っているかを確かめる。入っていなければ、持ち主に『返事待ちを追う一文をルーチンに足していいですか？』と質問カードで1回聞き、承認の後だけ足します。
