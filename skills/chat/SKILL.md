予定ばんの対話の早道

まず「予定ばんの運用ルール」を読み（同じ会話で読んであれば読み直さない）、正本は次だけを切り出して読む：`cd "$YOTEIBAN_REDESIGN_LIB" && python3 -m yoteiban_rd.rules_slice --task chat`（第2章）。個人の値（名前、カレンダーID、入口の住所、鍵、URL）は、このスキルに書かない。記憶と箱の設定から読む。
場面で足す章は下の1.のとおり。
大原則と安全の線は「予定ばんの運用ルール」が最優先で、早道でも弱めない。食い違う時は安全な方（書かない・送らない・消さない・聞く）を選ぶ。

本人が返事を待っている対話（質問カードへの答え、朝のまとめや案への要望、チャットでの頼み、口頭の「定期確認と同じことをして」、他の人への調整文の相談など。例であり、これに限らない）は、待ち時間を短くする。目安：単発で簡単な頼みは30秒前後。1つの調整は1〜3分、難しいものでも5分以内。いくつか重なっても合計1〜3分、最大5分。短いほど良い。本人が待たない定期確認（ルーチン）は対象外。
1. 読む：このスキルと場面のスキル1本だけ（同じ会話で読んであれば読み直さない）。正本は `rules_slice --task chat --add <場面の章>` だけ。正本の全文・自己試験・初回設定は読まない。迷っても、まず早道で返し、足りなければその後で読む。
   場面の章：答え・要望で予定を入れる／動かす／消す → --add 15,17,22／空きを探す・案を出す → --add 21.4,21.9,22／他の人への調整文 → --add 11,24:使わない設定,24:聞く必要の判断,24:相手の予定の確かめ,24:聞き方の文／急ぎ・夜 → --add 19,20.6。
2. 呼ぶ：要るものを1回の並列でまとめて呼ぶ（カレンダーは読む先の一覧の全部、メールやNotionも同じ1回に入れる）。スキルを読む1手と同じ並列に入れてよい（説明欄のとおり）。読んだ後で範囲や読む先が足りないと分かったら、足りない分だけをもう1回並列で呼ぶ（推測で埋めない）。範囲は要る日だけ（単発ならその日、口頭の定期確認は今日・明日と前回からの新着）。
   台帳（v2.3。運用の正）も同じ1回に入れる：開いている案件 `cases`、要る日の先読み `outlook_findings`、受け口が記録した新着 `raw_inputs`。読み込みは運用ルールの【道具】と同じ核（`PYTHONPATH="$YOTEIBAN_REPO/core:$YOTEIBAN_REPO/redesign/lib"`）の `yoteiban_core.ledger`。読めないときは「新しい台帳は未確認」と書き、無いものとして扱わない。Notion の8つの表は見る表で、同じ件は1つにまとめる。
   前の連絡を探すときは、原文の全文検索 `python3 -m yoteiban_core.search --config <設定> <語>`（--since・--until・--case-id で絞れる。読むだけ）。
3. 計算：計算係を1回だけ。予定が複数なら check-write に「news」でまとめて渡す（同じ依頼の中どうしの重なりも見る）。空きを探すときは `cli free`（日・時間帯・要る長さ。持ち主不明の予定との重なりは unconfirmed に出るので「未確認」と1行添える）。
4. 書く・記録する：書く・変える・消すは、早道でも 関所 → 書く（印）→ 読み戻す → 関所へ戻す、の順だけ（運用ルールの【書き込みの順】。関所は `python3 -m yoteiban_core.gate --config <設定> {check,result,reconcile}`）。読み戻しは同じ予定を1回取るだけにし、台帳への記録と返事の用意はその読み戻しと並列にしてよい。結果が分からなければ「実行結果不明（要照合）」にして書き直さない。安全の線は早道でも同じ（承認・ID照合・家用に書かない・送信は本人の「送る」の後）。下書きカレンダーは作らない（候補は会話と候補箱に置く）。
5. 返す：短く返す（3行くらいが目安）。要点を先に書く。要点がどうしても収まらないときは、要る分だけ行を足す。要る情報（日時・場所・相手・やること・「未確認」の印・断られた理由など）を削って短くしない。削るのは前置き・言い直し・説明の重ねだけ。要るときだけ質問カード1枚。
6. 口頭の定期確認：「定期確認と同じこと」は、縮めた受信の定期確認（見張り番が見ない入口・返事待ち・家用カレンダーの本人の予定）と、受け口が台帳に記録した前回からの新着を合わせたもの。見張り番が見る入口は読み直さない。前回の控え（`$YOTEIBAN_STATE/last_check.json`）からの差分だけを返す：`python3 -m yoteiban_rd.cli diff`（前回の控え・今回読んだもの・読めなかった入口・読んだ範囲を渡す）。full_needed が true（控えが無い・12時間より古い）のときだけ、全部を読む定期確認をする。読めなかった入口があれば「〇〇は未確認」と書き、「変わりなし」とは言わない（can_say_no_change が true のときだけ言える）。定期確認・朝のまとめ・口頭の確認の最後に、今回の控えを `cli snapshot`（または diff の snapshot）で last_check.json に保存する。
7. 目安を超えそうなとき（読む先が遅い・件数が多い）：分かった分を先に返し、読めていない入口は「未確認」と書く。残りは次の返事で続ける。

8. 待ち時間を記録する（手を増やさない）：最後の並列の1手（書く・記録する、または返事の直前の呼び出し）に、次の1行の追記を入れる。
   `echo '{"asked_at":"<本人の発言の時刻>","logged_at":"'"$(date '+%Y-%m-%d %H:%M:%S')"' JST","scene":"simple|dialog|multi","adjustments":<調整の数>}' >> $YOTEIBAN_STATE/latency.jsonl`
   scene：単発で簡単＝simple、本人が待つ対話＝dialog、複数の頼みを一度に＝multi。本人の名前・件名・本文は書かない（時刻と場面と数だけ）。ルーチン（本人が待たない定期確認）は記録しない。判定は `cli latency`（path にこのファイル）で行う。
