# 受付文先行の計測手順

受付文の先行送信はこの更新束では有効にしない。相手側で本人の承認を得て、架空依頼のみで次を計測してから採否を判断する。

1. 同じ端末・モデル・ネットワーク条件で、通常経路と「受付文を先に送る案」を各10回以上実施する。実際のメッセージは送らず、ローカルの送信関数を計測用stubに置き換える。
2. `received_at` から最初の応答生成、振り分け完了、担当処理完了までを単調時計で記録する。本文や相手IDは保存せず、試行番号・条件・経過ミリ秒・成否だけを残す。
3. 各条件の中央値と95パーセンタイル、失敗数を比較する。試行数が足りない場合は参考値と明記し、参考時間だけで改善を宣言しない。
4. 先行受付案を採用する場合も、送信先・文面・二重送信防止を本人に提示して別途承認を得る。承認前は設定を変えない。

この手順は計測方法だけを定義し、受付文の送信や本番の相手への連絡を行わない。
