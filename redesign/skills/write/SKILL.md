予定ばんのカレンダーへの書き込み

まず「予定ばんの運用ルール」を読み、正本の章を切り出して読む：`cd /home/box/agent-data/yoteiban-redesign/lib && python3 -m yoteiban_rd.rules_slice --task write`（第2・12・15・16・17・18・20・22・25章）。終了コード3なら全文を読んで続ける。版はGitの `VERSION` に従い、本文に版番号は直書きしない。
場面で足す章：移動や並びの余裕を足す → --add 21:余裕のとり方／［仮］の枠を洗い出す → --add 21:本人のしたいこと／夜に知らせるかを決める → --add 19／他の人の確認が要る・確認文 → --add 11,24／送信の状態 → --add 4.3。

【書く前の手順】
1. 承認を確かめる。強制追加（第16章）と［仮］（第17章）は、章の条件に全部当たるときだけ。推測した日時は強制追加にしない。開始・期限がもう過ぎていれば書かない（第18章）。
2. 書き込み先の照合（第15章）：対象のカレンダーIDを道具で記憶の『個人用カレンダーID』と照合する。違えば書かずに本人に報告する。家用カレンダー（primary・ファミリー）には書かない。
3. 検算（第15章）：計算係の check-write に、新しい予定と、その日の予定（個人用＋家用・ファミリーで本人・全員・わからないに分けたもの。第22章）を渡す。
   `cd /home/box/agent-data/yoteiban-redesign/lib && echo '{"new": {...}, "events": [...]}' | python3 -m yoteiban_rd.cli check-write`
   - conflicts（重なり）・duplicates（ダブり）・travel（移動の予定が無い・移動が間に合わない）が出たら、書かずに本人に2案を質問カードで出す。
   - unconfirmed（誰の予定か分からない家用の予定との重なり）は止めないが、案に「誰の予定か未確認」の1行を入れる。
   - 曜日は返り値の weekday を使う。文に曜日を書いたら `python3 -m yoteiban_rd.cli weekday` に {"text": "<文>", "base": "<今日>"} を渡し、mismatches が空であることを確かめる。
4. 移動の時間は家用カレンダーの本人の予定から逆算する。カレンダーで分かることは聞かない。移動や並びの余裕は第21章の「何分で足す」に従い、所要に2割や×1.2を足して余裕にはしない。所要の見積もりは中央値や「5件中4件が収まる時間」を使う。
5. 書いた後に読み直して、時刻とカレンダーIDを確かめる。結果が分からなければ「実行結果不明（要照合）」にして書き直さない（第25章の6）。

【強制追加】第16章。通知の型による幅の変更は第16章と第20章。知らせる時機は第19章・第20章（--add 19）。
【過ぎた予定】第18章。開始の時刻が文面に無い連絡には、(c)以外は当てない。(c)（家族・近い人の緊急事態の連絡）は、開始・期限の時刻が文面に無くても当てる。夜の扱い・言い方は第19章（--add 19）も見る。
【仮の追加】第17章。枠の洗い出しは第21章（--add 21:本人のしたいこと）、他の人の確認が要る時は第11章・第24章（--add 11,24）も見る。本人とのチャットでは、どれにするかを質問カード（ボタン）で聞き、番号つきの文字には切り替えない。カードが出せない外の出力先だけ、番号つきの文字で聞く。

【カレンダー】
正本の第2章（大原則）と第15章に従い、強制追加と［仮］以外は、書く前に件名・日時・場所・相手・所要・推測の印・出どころを見せ、本人が質問カードで選んだ時、または「登録して」「OK」と言った時だけ書きます。番号で選んでもらうのは、カードが出せない外の出力先だけです。調整の束は、承認された項目だけ書きます。他人のカレンダーへの招待・変更・削除は本人が明示した時だけです。
書いたら、事実だけの1行で返します。ほめ言葉・連続日数・ポイントは付けません。文例：「11/18(水) 14:00に『テスト塾 面談』を書きました」。

【説明欄の書き方】
カレンダーに書く予定の説明欄は、承認して書くもの・［自動］（強制追加）・［仮］のすべてで、必ず「いつ・どこで・何を」の形で始めます。「いつ：日時／どこで：場所（移動が要る時だけ。第12章）／何を：やること」。「何を」の行は必ず入れます。やることは全部、できるだけ短く、手順が複数なら、やる順の「・」の箇条書き。「何を」が決められない時は「何を：未定（本人に確認）」と書き、推測しません。この後ろに、［仮］なら「仮・本人の確認待ち」、そして出どころ・要約1行・推測の印などを続けます。
カレンダーやNotionへの書き込みが失敗した時は、正本の第25章の6に従います。

【他の人との予定調整機能】
正本の第24章（--add 24）に従います。他の人の確認が要る時は、何も書かず、まず本人に聞きます。聞き方の文と送信は「予定ばんの推測と確認」および第11章・第4.3節・第2章に従います（確認なしの送信はしない）。返事で日時が決まりそうなら、本人に確定してよいか質問カードで聞き、本人の承認があったときだけ、通常のルールで個人用カレンダーに書きます。他の人の予定は書きません。

変更の記録は Git の CHANGELOG.md に従う。
