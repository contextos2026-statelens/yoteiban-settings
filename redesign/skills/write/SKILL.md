# 書く前の検算（再設計版）

読む章：`rules_slice --task write`（2・15・16・17・18・20・22章）。20章は通知の型による自動追加の範囲のため。

1. 承認を確かめる（強制追加と［仮］は章の条件に当たるかを確かめる）。
2. 書き込み先のカレンダーIDを道具で照合する（記憶の『書き込み先』）。違えば書かずに報告。家用には書かない。
3. 計算係の `check-write` に、新しい予定とその日の予定（個人用＋家用の本人の予定）を渡す。重なり・移動の抜けが出たら、書かずに本人に2案をボタンで出す。
4. 移動の時間は家用カレンダーの本人の予定から逆算する。カレンダーで分かることは聞かない。面接指導は1コマずつ、重なりを確かめてから。
5. 書いた後に読み直して、時刻とカレンダーIDを確かめる。台帳の案件を「実行完了」にする。結果が分からなければ「実行結果不明（要照合）」にして書き直さない。
